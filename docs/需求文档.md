## 1. 产品定位

一款以胡牌爽感为核心卖点的 3D 单机麻将游戏。玩家和三名对手连续打若干局；番型越突出，胡牌场面越强。桌面和环境支持主题热切换，对手可使用内置逻辑或用户配置的外接 AI。

### 1.1 目标

1. 完整、正确地执行一套范围明确的四人麻将规则。
2. 用 basic、big、top 三档胡牌场面制造可截图、可重播的高光时刻。
3. 用经典绿绒与中式宫廷两套主题验证外观数据化和运行时热切换。
4. 规则核心可测试、可复现，渲染与规则互不依赖。
5. 无云服务也能完整游玩，外接 AI 只是可选增强。

### 1.2 不做

- 真钱、筹码输赢、博彩、内购、广告或主题解锁。
- 联网多人、账号、登录、云存档、排行榜和社交。
- Unity 迁移、原生 App、PWA、小游戏平台。
- 用户自制主题、在线主题下载。
- 完整国标、四川或广东麻将。
- MVP 1.0 前的移动端适配、触控和竖屏布局。

## 2. 交付边界

### 2.1 可玩纵切版

完成 M3 后称为“可玩纵切版”，包括：

- 桌面 Chrome / Edge。
- 爽胡规则的一场完整游戏：玩家 + 三名 easy 对手。
- 经典绿绒、中式宫廷两套主题。
- 三档胡牌场面与多家胡牌顺序播放。
- 本地存档、动作日志和开发者回放。
- 可选 OpenAI-compatible 外接 AI、20 秒回退和 mock 测试。
- 单一桌面画质；允许继续使用 CPU 粒子。

### 2.2 MVP 1.0

M6 完成后称为“MVP 1.0”。在纵切版之上增加：

- 桌面 Chrome、Edge、Firefox、Safari。
- low / mid / high 三档画质、自动检测和动态降级。
- GPU 粒子与 CPU 兜底。
- 字体子集、性能优化、资源释放和完整兼容性测试。
- GitHub Pages 与任意静态服务器部署。

MVP 1.0 仍只有 easy 内置对手与可选外接 AI；normal、hard 延后。仍只提供本地合成音效，不加入 BGM、真人报番和采样音频。主题仍为两套，天空只实现纯色和渐变。

## 3. 爽胡规则

### 3.1 牌组

- 共 136 张。
- 万、筒、索各 1–9，每张四枚。
- 字牌为东、南、西、北、中、发、白，每张四枚。
- 没有花牌。
- 每张实体牌有内部唯一 ID；规则按牌码判断，事件与回放按实体 ID 区分。

### 3.2 一局与一场

- 一局从发牌开始，到一家或多家胡牌，或牌墙耗尽流局。
- 一场由连续若干局组成。每局结算后，玩家选择“下一局”或“结束”。
- 没有整场总分或胜负。
- 第一局随机选择庄家，不掷骰。
- 庄家起手 14 张并先出牌；其他家起手 13 张。
- 一家胡牌时，下一局由该家坐庄。
- 一炮多响时，从点炮者下家开始数，第一位胡牌者坐庄。
- 流局时庄家不变。
- HUD 只显示“庄”，不显示圈风或门风。
- 玩家座位始终位于画面下方，不因庄家变化旋转。

### 3.3 正常行牌

1. 正常摸牌从牌墙头部取得。
2. 玩家或对手选择合法动作。
3. 出牌进入该家的牌河。
4. 其他家进入响应窗口。
5. 无响应时轮到下家摸牌。

玩家没有操作倒计时。对手有短暂表现延迟，但不影响规则。

### 3.4 吃、碰、杠

- 吃：仅能使用上家打出的牌组成顺子。
- 碰：可使用任意一家打出的牌组成刻子。
- 明杠：使用别人打出的牌与手中三张相同牌组成杠。
- 暗杠：自己手中四张相同牌组成杠。
- 加杠：在已有碰上加入自己得到的第四张牌。
- 不允许抢杠胡。
- 暗杠和加杠只能在自己摸牌后、出牌前执行。
- 杠成立后从牌墙尾部补一张，再继续决定杠或出牌。
- 牌墙已无可补牌时不能杠。
- 被吃、碰、明杠的牌离开出牌者牌河，进入响应者副露，并标明来源座位。
- 吃或碰成功后由响应者出牌；明杠成功后先补牌再出牌；之后从响应者下家继续。
- 有多种吃法时，动作必须明确使用哪两张手牌。

### 3.5 响应优先级

一次出牌后先收集所有响应，再统一裁决：

1. 所有可以胡的家都成功。
2. 无人胡时，明杠优先于碰，碰优先于吃。
3. 同级冲突时，从出牌者下家起，距离最近者成功。

如果玩家拥有合法响应，系统等待玩家明确选择；AI 的选择可提前计算，但不得提前暴露。选择“过”只放弃当前这次机会，之后遇到相同牌仍可响应。

牌墙最后一次正常摸牌被打出后，只允许胡；无人胡则立即流局。

### 3.6 胡牌与番型

承认以下番型：

| 番型 | 定义 | 番数 | 特效档 |
| --- | --- | ---: | --- |
| 平胡 | 四组面子加一对将，且未命中其他番型；面子可为顺子或刻子，可含字牌 | 1 | basic |
| 碰碰胡 | 四组刻子或杠，加一对将 | 1 | big |
| 清一色 | 手牌与副露只含一种数牌花色，不含字牌 | 1 | big |
| 七对 | 手牌由七个对子组成；四张相同计作两对 | 1 | big |
| 十三幺 | 无副露；三种数牌的一九和七张字牌各一张，再重复其中一张 | 1 | top |
| 杠上开花 | 杠后补进的牌使自己胡牌 | 1 | big |

规则：

- 平胡只在没有命中其他番型时计入。
- 其他番型可以叠加。例如清一色 + 杠上开花为 2 番。
- 不设起胡门槛。
- 自摸不加倍，庄家不加番。
- 不使用钱、筹码或支付关系。
- 玩家可以对可胡牌选择“过”；AI 只要能胡就一定胡。
- 一手命中多条番型时，特效档取其中最高档，不按总番数阈值计算。

### 3.7 一炮多响

- 同一张出牌可以让两家或三家同时胡牌。
- 核心一次结算全部赢家，不采用截胡。
- 各家分别计算番型和番数。
- 胡牌场面先按 top、big、basic 排序；同档从点炮者下家起按座位顺序播放。
- 下一局庄家按 3.2 的座位规则确定。

### 3.8 流局

- 牌墙耗尽且无人胡牌时流局。
- 翻开四家手牌。
- 标明每家是否听牌；听牌者列出可胡牌。
- 不计番、不产生分数变化。
- 流局没有胡牌场面。

## 4. 玩家操作

### 4.1 手牌

- 手牌按万、筒、索、字自动排序。
- 刚摸的牌暂时独立放在最右侧，直到出牌或用于杠。
- 第一版不支持手动调整牌序。

### 4.2 出牌

- 第一次点击使牌上浮并选中。
- 再次点击同一张牌确认出牌。
- 桌面端同时支持拖入牌河。
- 不增加额外确认弹窗。
- 已确认的出牌、吃碰杠胡不可撤销。

### 4.3 操作按钮

- 根据合法动作显示吃、碰、杠、胡、过。
- 多种吃法必须选择具体组合。
- 可以胡时显示“胡”和“过”，不自动替玩家胡牌。
- 第一版不向玩家显示听牌提示、牌效提示或出牌建议。

## 5. 对手与外接 AI

### 5.1 内置对手

- MVP 1.0 只实现 easy。
- easy 只能读取公开信息和自己的手牌。
- 洗牌、easy 决策及所有影响牌局的随机行为使用同一个可序列化种子随机源。
- 禁止规则和 AI 直接使用 `Math.random()`。
- normal、hard 属于后续版本。

### 5.2 统一决策边界

每个对手的决策来源可以独立选择：

- 内置 easy。
- 外接 OpenAI-compatible AI。

三家共用同一代理地址、模型名和代理令牌配置。引擎向决策来源提供合法动作集合，返回值必须选择其中一个具体动作；非法结果自动回退 easy。

### 5.3 外接 AI 可见信息

只发送：

- 该座位自己的手牌。
- 公开副露和牌河。
- 剩余牌数。
- 庄家、当前轮次。
- 当前合法动作。

不得发送：

- 其他家的隐藏手牌。
- 牌墙顺序。
- 随机种子。
- 模型厂商 API Key。

### 5.4 超时与并发

- 一次响应窗口中，多个 AI 请求并行发送。
- 共用 20 秒截止时间，不逐家串行等待。
- 超时、网络失败、格式错误或非法动作均由 easy 接手这一手。
- 对手自己的回合也最多等待 20 秒。

### 5.5 凭据与告知

- 浏览器不保存模型厂商 API Key。
- 云模型经用户自行部署的代理服务接入。
- 代理地址和模型名可以持久化。
- 代理令牌只保存在当前浏览器会话，不写入 localStorage、IndexedDB、日志或导出。
- 首次启用前显示代理地址、会发送与不会发送的字段，用户确认后才启用。
- 生产只接受 HTTPS 代理；本机开发允许 `http://localhost`。
- 代理负责正确配置 CORS。

## 6. 规则核心、状态与事件

### 6.1 核心边界

- 规则核心是纯 TypeScript，不依赖 DOM、Three.js、音频或网络。
- 核心接收命令，返回新状态和领域事件。
- 当前状态是权威，不采用完整 Event Sourcing。
- 渲染、UI、音频和特效只能订阅事件与读取公开快照，不得修改核心状态。

### 6.2 规则定义

- 胡牌、番型、响应和状态机由带测试的 TypeScript `RuleSet` 实现。
- JSON 只承载可校验的常量和展示配置。
- 不承诺只修改 JSON 就能新增完整规则。
- 当前唯一规则标识为 `shuanghu-v1`。

### 6.3 事件

核心事件只包含领域事实。例如：

- `TileDrawn`
- `TileDiscarded`
- `MeldDeclared`
- `KongDeclared`
- `HandWon`
- `HandExhausted`

`HandWon` 原子地包含全部赢家。胡牌事件包含赢家、牌、点炮或自摸、手牌、副露、番型和番数；不包含特效档、横幅、主题或颜色。

表现层根据番型映射特效档和横幅，并在播放开始时取得主题配色。

### 6.4 存档与动作日志

- 每个已完成动作后保存当前场快照。
- 快照带 `schemaVersion` 和随机源状态。
- 有明确迁移器时迁移旧快照；否则提示不兼容，允许导出后重新开始。
- 设置、音量和当前主题存入 localStorage。
- 当前场快照和动作日志存入 IndexedDB。
- 自动保留最近 20 场动作日志；当前存档另计。
- 主菜单显示“继续”。
- 主动结束一场后清除当前存档。
- 提供导出、清除本地数据。

动作日志记录初始种子和最终采用的合法动作。回放直接重放动作，不重新调用外接 AI。

MVP 1.0 只提供开发者导入、导出和完整回放；玩家只能重播胡牌场面。

## 7. 胡牌场面系统

### 7.1 分层

| 特效档 | 对应番型 | 基准场面 |
| --- | --- | --- |
| basic | 平胡 | 手牌波浪弹起、金色描边、闪粉 |
| big | 碰碰胡、清一色、七对、杠上开花 | 牌聚拢、光柱、涟漪、冲击粒子 |
| top | 十三幺 | 慢动作、白闪、牌化粒子、聚成“胡”字 |

只有胡牌拥有特效档。吃、碰、杠只播放必要的牌移动反馈；流局直接进入流局结算。

### 7.2 时间轴

- 特效以 JSON 时间轴配置。
- 轨道组件至少包含 camera、tiles、pillar、ripple、emitter、glyph、banner、shake、flash、bloom、slowmo、sfx。
- 每个组件实现开始、更新和释放生命周期。
- 配置通过 JSON Schema 校验。
- 内置配置错误阻断构建；运行时资源失败使用回退。

### 7.3 多家胡牌

- 每位赢家播放一段完整场面。
- 最高特效档先播，同档按座位顺序。
- 镜头转向当前赢家，播完后进入下一位；全部结束后回到玩家视角并进入结算。
- 牌局输入在播放期间锁定。
- 仍允许跳过、调音量、切换主题和切换“减少动态效果”。

### 7.4 跳过与重播

- 玩家可跳过当前赢家的场面并进入下一位。
- 可开启“自动跳过对手场面”。
- 自己的场面默认完整播放。
- 结算面板为每位赢家提供单独重播，并提供按原顺序全部重播。

### 7.5 减少动态效果

- 关闭震屏、猛推和快速转镜。
- 保留牌动画、横幅和粒子。
- 默认跟随 `prefers-reduced-motion`。
- 玩家设置可以覆盖系统偏好。

### 7.6 主题切换中的场面

桌面和天空立即开始主题过渡；已经播放中的胡牌场面冻结其开始时的配色并播放完。新配色从下一段胡牌场面开始生效。

## 8. 主题

### 8.1 主题边界

主题可以拥有：

- 桌绒、桌框、中央标志。
- 纯色或渐变天空、雾和灯光。
- 环境粒子。
- 牌背。
- 特效配色与后处理参数。
- 可选 BGM 和音效覆盖字段。
- 预览图和质量覆盖。

主题不能改变：

- 牌面花色和点数画法。
- 桌面尺寸、牌墙位置、玩法布局。
- 胡牌场面的时间轴和节奏。
- 横幅文字内容。

横幅文字由胡牌事实决定，颜色由主题决定。

### 8.2 经典绿绒

- 复现现有 Demo 外观。
- 绿色程序桌绒、木框、金色“雀”字与双环。
- 深色纯色天空与雾。
- 暖光、金色浮尘、绿色牌背、金橙特效配色。

### 8.3 中式宫廷

- 程序生成朱红织锦桌面。
- 深色红木框和金边。
- 黄昏宫墙渐变天空。
- 朱红底金色云纹牌背。
- 花瓣环境粒子。
- 金色篆体“福”字和双金环。
- MVP 不使用 HDR、外部贴图或 BGM。

### 8.4 加载与切换

- 主菜单与对局设置都能切换主题。
- 切换不刷新页面、不打断牌局。
- 主题过渡目标为 0.3–0.6 秒，不出现黑屏或单帧闪烁。
- 首次启动只加载经典绿绒；中式宫廷按需加载。
- 记住最后选择；保存值失效时回到经典绿绒。
- 单模块失败时，该模块回退经典绿绒。
- 整份配置无效时，整套回退经典绿绒。
- 回退显示非阻塞提示并记录本地日志。
- 切走主题延迟释放 GPU 资源，保留最近一套供快速切回。

### 8.5 主题发现与范围

- 主题随游戏发布。
- 新增合法主题目录后，构建时自动发现，不修改业务代码。
- 第一版不支持导入、UGC 或在线下载。
- MVP 只实现 `color` 与 `gradient` 天空。
- cubemap、HDR、shader 天空属于后续版本。
- 两套 MVP 主题各自的按需资源压缩传输量不超过 1 MB。
- 未来含 HDR 或贴图的单主题预算可放宽到 5 MB。

## 9. 音频与字体

### 9.1 音频

- MVP 只使用本地程序合成音效。
- 包含摸牌、出牌、吃、碰、杠、胡及三档场面音效。
- 不包含 BGM、真人报番或外部采样素材。
- 主题保留音频字段，但两套 MVP 主题均为空。
- 主音量和音效音量分开设置并持久化。
- 移动端音频解锁留到移动适配阶段。

### 9.2 字体

- UI 使用思源黑体。
- 牌面、横幅、“胡”和“福”使用思源宋体。
- 构建时只保留实际使用字符并输出 WOFF2。
- 发行物保留 SIL OFL 1.1 许可证。
- 字体加载完成后再绘制牌面 Canvas。
- 顶级场面的“胡”字点阵离线生成，不依赖运行时系统字体。

## 10. UI

### 10.1 主菜单

- 开始一场。
- 继续最近一场。
- 主题选择。
- 设置。
- 开发者模式入口。

### 10.2 对局 HUD

- 玩家手牌、四家牌河和副露。
- 剩余牌数与庄家标记。
- 合法操作按钮。
- 当前外接 AI 等待和回退状态。
- 不显示门风、圈风、总分或筹码。

### 10.3 结算

胡牌结算：

- 列出每位赢家。
- 列出各自番型和番数。
- 显示对应特效档。
- 单独重播或全部重播。
- 下一局或结束。

流局结算：

- 展示四家手牌。
- 标明听牌状态和可胡牌。
- 下一局或结束。

### 10.4 文案

- 首发只显示简体中文。
- 所有用户文案集中管理，为未来语言包保留边界。
- 统一使用“十三幺”，不使用“国士无双”或“役满”。
- 不再使用“番数翻倍”等占位文案。

## 11. 画质与性能

### 11.1 画质档

MVP 1.0 提供：

| 档位 | DPR | 阴影 | Bloom | 粒子 | 天空 |
| --- | ---: | --- | --- | --- | --- |
| low | 1.0 | 关闭或低分辨率 | 关闭或半分辨率 | 大幅减少，CPU 可兜底 | 简化渐变 |
| mid | ≤1.5 | 1024² | 开启 | 中等 | 主题原配置 |
| high | ≤2.0 | 2048² PCF | 开启 | 完整 GPU 粒子 | 主题原配置 |

纵切版只有单一桌面画质，不以 GPU 粒子为门槛。

### 11.2 自动降级

- 首次根据 GPU 信息和短时间实测选择档位。
- 最近连续 5 秒平均帧率低于目标档 80% 时降一档。
- 自动策略只降不升，下一场重新评估。
- 玩家手动选档后不再自动变更。

### 11.3 性能基线

MVP 1.0 的桌面低基线：

- Intel UHD 620 级别集显。
- 1920×1080。
- 最新版 Chrome。
- mid 正常对局目标 60 fps。
- top 场面不低于 30 fps。

纵切版记录性能但不阻断；MVP 1.0 才执行门槛。

### 11.4 资源和加载

- 首屏压缩传输量 ≤3 MB，包含 Three.js、代码、默认主题和字体。
- 冷缓存、模拟 Fast 4G 下 ≤3 秒进入主菜单。
- 字体和默认主题未完成前显示真实加载进度。
- 外接 AI 不计入启动时间。
- 静态场景目标 ≤100 draw calls。
- 手牌、牌墙、牌河优先使用 InstancedMesh。
- 牌面使用图集。
- 连续 50 局、100 次胡牌场面和20 次主题切换后，不应出现持续内存或显存增长。

### 11.5 WebGL

- 必须支持 WebGL2。
- 不维护 WebGL1 降级实现。
- 不支持时显示明确的兼容性说明。
- 处理 WebGL context lost，并在可恢复时重建渲染资源。

## 13. 部署、安全与隐私

### 13.1 部署

- 默认发布到 GitHub Pages。
- 同时支持任意静态服务器。
- 构建支持非域名根路径。
- 不做 PWA 或 Service Worker。
- 除可选外接 AI 外，生产构建不访问网络。

### 13.2 CSP

GitHub Pages 无法针对运行时用户输入的任意代理生成精确 CSP：

- `connect-src` 允许同源与 HTTPS。
- 应用代码只请求用户配置的唯一代理地址。
- 本机开发额外允许 localhost。
- 若未来要求严格域名隔离，改为构建期白名单或同源后端。

### 13.3 隐私

- 不集成分析 SDK。
- 不上传牌局、性能或崩溃数据。
- 调试日志只保存在本地，由用户主动导出。
- 外接 AI 数据边界按第 5 节执行。

### 13.4 许可证

- 不擅自为仓库默认选择 MIT 或其他许可证。
- 未确定项目前保持无 LICENSE 或保持仓库私有。
- README 明确 Three.js、字体等第三方内容遵循各自许可证。

## 14. 测试与 CI

### 14.1 规则测试

- 每个番型至少一个正例和一个反例。
- 覆盖副露、四张算两对、平胡不叠加、组合番。
- 覆盖一炮多响、响应优先级和最后一张。
- 覆盖明杠、暗杠、加杠、补牌和杠上开花。
- 规则核心要求 100% 分支覆盖。
- 渲染代码不设统一覆盖率门槛。

### 14.2 随机自对弈

至少一万局，检查：

- 每一步动作合法。
- 实体牌不重复、不丢失，区域总数守恒。
- 状态机不死锁。
- 每局只有一个终止状态。
- 失败时输出种子与动作日志。

### 14.3 外接 AI

CI 使用本地 mock OpenAI-compatible 服务，覆盖：

- 正常合法动作。
- 20 秒超时。
- 网络失败。
- 格式错误。
- 非法动作。
- easy 回退。

CI 不调用真实模型。

### 14.4 视觉测试

- 固定时钟、粒子种子、窗口、DPR、主题和截图时点。
- 与三档基线做宽松像素差异检查。
- 截图差异作为 CI artifact。
- 人工最终确认节奏、亮度和冲击力后才更新基线。

### 14.5 GitHub Actions

每次变更执行：

1. 安装依赖。
2. 类型检查。
3. 单元测试和覆盖率。
4. 配置 Schema 校验。
5. 生产构建。
6. Playwright 流程和视觉测试。

## 16. 验收标准

| 编号 | 验收项 | 标准 |
| --- | --- | --- |
| AC1 | 完整一局 | 发牌、摸打、响应、吃碰杠、胡或流局都能完成 |
| AC2 | 规则正确 | 规则测试 100% 通过，核心分支覆盖 100% |
| AC3 | 随机稳定 | 一万局自对弈无非法动作、牌丢失或死锁 |
| AC4 | 一炮多响 | 全部赢家原子结算，场面顺序与庄家规则正确 |
| AC5 | 特效映射 | 平胡 basic；碰碰胡、清一色、七对、杠上开花 big；十三幺 top |
| AC6 | 特效启动 | 胡牌结算后 100 ms 内进入第一段场面调度 |
| AC7 | 特效观感 | 固定条件截图通过宽松差异检查，人工确认不低于原型 |
| AC8 | 主题切换 | 对局中切换不打断牌局，0.3–0.6 秒过渡，无黑屏闪烁 |
| AC9 | 主题回退 | 单模块和整套配置失败均按规则回退，游戏继续运行 |
| AC10 | 资源释放 | 20 次主题切换后显存不持续增长 |
| AC11 | 外接 AI | 正常、超时、错误和非法动作均有确定行为，秘密不持久化 |
| AC12 | 存档 | 每个动作后可恢复；版本不兼容不静默误读 |
| AC13 | 字体 | 无系统中文字体时，牌面、横幅和粒子字形一致 |
| AC14 | 首包 | 压缩传输量 ≤3 MB |
| AC15 | 启动 | 冷缓存 Fast 4G 下 ≤3 秒进入主菜单 |
| AC16 | 性能 | UHD 620 级别集显、1080p、Chrome、mid 正常对局目标 60 fps，top ≥30 fps |
| AC17 | 稳定 | 连续 50 局、100 次场面和20 次主题切换后无持续内存增长 |
| AC18 | 浏览器 | 桌面 Chrome、Edge、Firefox、Safari 可完整游玩 |
| AC19 | 离线 | 除外接 AI 外，断网后从本地静态服务器可完整游玩 |
| AC20 | 隐私 | 无分析 SDK和后台上传；日志只在用户主动操作时导出 |
